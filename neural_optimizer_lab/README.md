# OptiLab — порівняльне дослідження алгоритмів оптимізації

Локальний безкоштовний Python-проєкт для порівняння SGD, Momentum, RMSProp та Adam під час навчання невеликої нейронної мережі на нелінійно роздільних даних. Інтерфейс українською мовою має темну аналітичну тему, таблицю результатів, графіки та вбудовану довідку.

## Що реалізовано

- MLP з архітектурою `2 → 16 ReLU → 1 sigmoid` на NumPy.
- Стабільна Binary Cross-Entropy через `numpy.logaddexp`.
- Backpropagation, написаний вручну, та перевірка градієнтів центральними скінченними різницями.
- Власні реалізації SGD, Momentum, RMSProp та Adam (із поправкою зміщення моментів).
- Дані `moons`, `circles`, `xor`, фіксовані seed, train/test split і стандартизація без витоку статистики тестової вибірки.
- Повторні запуски, sweep learning rate, критерій цільової BCE та зупинка на плато.
- Accuracy, precision, recall, F1, BCE, кількість епох, часові вимірювання, середні значення та стандартні відхилення.
- Графіки PNG, CSV, JSON та автоматичний текстовий звіт; дані зберігаються після кожного завершеного запуску.
- Автоматичні тести без додаткового тестового фреймворку (використовується вбудований `unittest`).

## Безкоштовність і робота офлайн

Усі обчислення виконуються на вашому комп'ютері. Не використовуються платні API, хмарні сервіси, підписки або відеокарта. Після одноразового встановлення пакетів інтернет для запуску й експериментів не потрібен. Основний код використовує NumPy; Matplotlib будує графіки, scikit-learn — генерує деякі синтетичні дані, ділить вибірку та масштабує ознаки, pandas формує таблиці.

Усі залежності безкоштовні й мають відкриті ліцензії. `tkinter` входить до стандартної бібліотеки більшості інсталяцій Python для Windows. У проєкті не потрібні `torch`, TensorFlow, Keras, CustomTkinter або платні UI-компоненти.

## Вимоги

Рекомендовано Python 3.11 або 3.12 (також можна використовувати сумісні новіші версії). Потрібно встановити пакети з `requirements.txt`:

- `numpy>=1.24`
- `matplotlib>=3.7`
- `scikit-learn>=1.3`
- `pandas>=2.0`

## Запуск у Visual Studio Code на Windows

### 1. Відкрити проєкт

1. Розпакуйте ZIP-архів у зручну теку, наприклад `Desktop\neural_optimizer_lab`.
2. Запустіть VS Code.
3. Оберіть **File → Open Folder...** і відкрийте саме теку `neural_optimizer_lab`, у якій лежать `main.py` і `requirements.txt`.
4. За потреби встановіть офіційне розширення **Python** від Microsoft у VS Code.

### 2. Створити віртуальне середовище

Відкрийте **Terminal → New Terminal**. Переконайтеся, що термінал відкрився в кореневій теці проєкту, і виконайте:

```powershell
py -3.11 -m venv .venv
```

Якщо команда не знаходить Python 3.11, а інша версія Python уже встановлена, можна виконати:

```powershell
python -m venv .venv
```

### 3. Активувати середовище та встановити пакети

У терміналі PowerShell VS Code виконайте:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Якщо PowerShell блокує активацію саме в поточному терміналі, можна тимчасово дозволити її для цього процесу:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
.\.venv\Scripts\Activate.ps1
```

Ця команда не змінює політику для всього комп'ютера. Альтернативно можна не активувати середовище, а викликати його Python напряму: `.\.venv\Scripts\python.exe main.py`.

### 4. Вибрати інтерпретатор у VS Code

Натисніть `Ctrl+Shift+P`, введіть **Python: Select Interpreter** і виберіть інтерпретатор із `.venv`. Зазвичай він має шлях, схожий на `.venv\Scripts\python.exe`.

### 5. Запустити графічну програму

У терміналі, перебуваючи в кореневій теці проєкту й за активного `.venv`, виконайте:

```powershell
python main.py
```

Відкриється вікно OptiLab. Початкові налаштування вже задані. Залиште відміченими всі чотири оптимізатори, виберіть один набір даних і натисніть **«Запустити експерименти»**. Після завершення таблиця й графіки з'являться в інтерфейсі. Для порівняння різної геометрії активуйте **«Порівняти всі три геометрії»**. Для дослідження learning rate увімкніть sweep — програма запустить базову швидкість і значення, що вдесятеро менше та більше (у допустимих межах).

Поточні експерименти виконуються у фоновому потоці, тому вікно має залишатися чутливим до дій користувача. Кнопка **«Скасувати запуск»** зупиняє роботу без видалення вже збережених результатів.

## Де шукати результати

У кореневій теці проєкту автоматично створюється `results`. Кожна серія експериментів має власну теку на кшталт `results/run_20261023_143000_123456/`.

- `runs.csv` — метрики кожного запуску та причина завершення;
- `history.csv` — втрати й accuracy після кожної епохи;
- `summary.csv` — середні значення, стандартні відхилення та кількість спостережень;
- `details.json` — конфігурація, докладні записи й історії;
- `report_uk.txt` — стислий звіт, автоматично сформований за фактичними результатами;
- `plots/` — PNG із даними, кривими втрат, порівнянням точності, збіжністю, learning rate та межею рішень.

CSV створюються в кодуванні UTF-8 із BOM, щоб зазвичай коректно відкриватися в Microsoft Excel. Після кожного завершеного запуску таблиці й деталі оновлюються, тож завершені експерименти не губляться, якщо пізніший запуск зазнає числової помилки.

## Як запустити автоматичні тести

У кореневій теці проєкту виконайте:

```powershell
python -m unittest discover -s tests -v
```

Тести перевіряють форми матриць, діапазон імовірностей, числову стабільність BCE, відтворюваність, градієнти методом скінченних різниць, формули оновлення оптимізаторів і тестовий повний цикл зі збереженням таблиць та PNG.

## Як тлумачити критерій зупинки

`epochs_to_target` заповнюється тільки в разі, коли навчальна BCE справді досягла заданого порога. Якщо модель зупинилася через плато або вичерпала максимум епох, поріг вважається **не досягнутим**. Така поведінка не дозволяє помилково назвати максимальну кількість епох успішною збіжністю. Кінцева BCE і accuracy аналізуються окремо.

## Типові проблеми

**`ModuleNotFoundError` для NumPy/Matplotlib/sklearn/pandas.** Активуйте `.venv` і повторно виконайте `python -m pip install -r requirements.txt`.

**Вікно не відкривається або повідомляє про відсутній Tk.** Перевірте встановлення Python з підтримкою Tcl/Tk. На Windows офіційний інсталятор Python зазвичай містить цей компонент.

**Команда `py` не знайдена.** Спробуйте `python -m venv .venv` або встановіть Python з офіційного дистрибутива й увімкніть додавання Python до PATH.

**Активація заблокована PowerShell.** Застосуйте локальну команду `Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned`, як наведено вище, або запускайте `.\.venv\Scripts\python.exe main.py` без активації.

**Дуже багато експериментів або тривале виконання.** Зменште `Максимум епох`, `Повторів` або вимкніть sweep. Якщо обрано всі три набори, чотири оптимізатори, sweep і багато повторів, кількість запусків збільшується у відповідній пропорції.

**Запуск позначено як числова помилка.** Перегляньте `error_message` в `runs.csv` і налаштування у `config.json`. Такий запуск не входить до агрегованих середніх, але залишається у файлі для прозорості.
